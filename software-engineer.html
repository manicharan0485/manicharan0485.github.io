An operations console for a fictional Mittelstand company running Windows, Hyper-V, vSphere and a small Kubernetes cluster across Aachen, Köln and Düsseldorf. Triage first

Problems sort to the top

The fleet table orders hosts critical, then warning, then healthy. The first row you read is the first thing you fix. Alphabetical order only applies within each group.

Color has one job

Status color is never decoration

Green, amber and red mean healthy, warning and critical everywhere on the page. The blue accent is only for interaction and neutral data, so a red pixel always means something.

Shape over numbers

Backups as a 14-night heatmap

A success percentage hides patterns. The grid shows at a glance that AAC-FS01 failed two nights in a row, which points to a VSS problem and not a one-off network blip.

Thresholds on the chart

The 80 % line is drawn, not implied

Storage bars and CPU charts carry the alert threshold as a mark. You can see how close a datastore is to paging someone without reading the alert rules.

Approach

How I design and build

Summary before detail

Four numbers answer "is everything okay?". Everything below them answers "what exactly is wrong?".

Use the admin's words

Hostnames, volume letters, Patch Tuesday baselines and KB numbers. The UI speaks the same language as the runbook.

Every alert says what to do

"Volume D: at 93 %" comes with growth rate and a projected full date, so the next step is obvious.
